# Git 分支模块重构方案

- 编写日期：2026-10-29
- 状态：阶段一至四已实施，定向回归与 TypeScript 检查通过
- 所属项目：Cota
- 说明：本文同时记录目标设计和实施进度；已完成范围见第 11 节，其余阶段不代表已经实现。

## 1. 背景与目标

当前已经具备分支管理、远端同步和本地变更监听能力，但实现分散在通用 Git 服务、组件状态和不同的数据读取链路中，缺少统一的分支资源管理。

主要问题：

1. `SourceControlPanel` 使用组件内 `useState` 保存分支列表，不同工作区不能共享同仓库的分支数据。
2. 分支读取依赖 `session.refreshed`，普通文件状态刷新也会触发分支和 Worktree 信息重读。
3. 分支数据没有统一的请求合并、失效、后台刷新和错误保留机制。
4. Git 本地远端跟踪引用与 MR 弹窗的平台分支独立读取，没有统一协调缓存生命周期。
5. 同仓库的只读平台网络请求与本地读取共用仓库级串行入口，可能产生排队。

重构目标：

- 统一分支查询、操作、同步、缓存及失效入口。
- 同仓库共享分支引用，不同工作区隔离当前分支和操作状态。
- 减少重复读取，并确保外部 Git 操作、部分失败和工作区删除后数据能够正确收敛。
- 保留现有授权校验、仓库锁、Git 安全参数及 MR 防重复保护。
- 渐进迁移，不推倒重写整个 Git 模块。

核心原则：

> 共享分支引用，隔离工作区状态；缓存服务于展示，实时校验服务于写操作。

## 3. 范围与非目标

### 3.1 本轮范围

- 统一分支数据读取、共享、刷新和失效。
- 收拢创建、创建并切换、切换、删除本地分支操作。
- 收拢 Fetch、Pull、Push、Publish、Sync 调度。
- 处理并发请求合并、旧响应丢弃、写后刷新和生命周期清理。
- 接入 Git 更改、比较、Worktree 创建、侧栏和 MR 弹窗。

### 3.2 本轮不扩展

- 分支重命名或远端分支删除。
- 自动 Fetch 或自动 Prune。
- 强制推送、自动 stash 或自动解决冲突。
- 缓存持久化、数据库缓存或通用查询框架。
- 新增依赖或重做分支选择器 UI。

先完整组织已有能力，不借重构增加额外功能。

## 4. 数据边界

不能将当前完整的 `GitReferences` 直接按仓库缓存。它混合了共享分支引用、Worktree 占用信息和当前目录解析出来的远端配置，需要先拆分。

### 4.1 仓库共享数据

由主进程基于验证过的真实 `repoCommonDir` 识别共享仓库，保存：

- 本地分支引用和远端跟踪引用。
- 每条引用的提交 OID、提交日期和标题。
- 远端 HEAD 符号引用。
- 分支与 Worktree 的占用关系。

同仓库不同 Worktree 共用这一份数据，不在其中保存“当前分支”。

仓库身份和缓存键由主进程解析，不能直接信任渲染进程提交的路径或仓库 ID。目录替换、仓库重新初始化及绑定变化时，应使旧缓存失效，不能因路径相同而继续复用。

### 4.2 工作区视图

按 `workspaceId` 隔离：

- 当前分支、HEAD 和上游。
- ahead / behind。
- 当前工作区解析出的远端配置。
- 当前操作、加载和错误状态。

第一阶段继续复用 `useSourceControl.sessions[id].status` 中的当前分支等信息，由分支模块组合成工作区视图，不复制另一份互相竞争的状态。

远端配置不能无条件在整个仓库间共享：Git 支持 `config.worktree`，不同 Worktree 的配置可能不同。

### 4.3 托管平台远端分支

GitHub/GitLab API 返回的服务器分支独立管理。缓存身份至少包含：

```text
平台 + Host + 平台仓库身份 + 当前账号
```

账号切换、仓库身份变化和权限失败时，需要清理或隔离对应资源。

平台分支与本地 `refs/remotes/*` 是不同数据源：

- Git 比较使用本地已获取的引用。
- MR 选择器使用平台分支。
- 不拼接两份列表后宣称是“最新远端分支”。

## 5. 模块结构与职责

建议先新增三个主要文件，沿用现有服务，不建立通用资源管理框架：

```text
src/shared/git-branches.ts
  分支契约、快照、操作类型和变更通知

src/main/git/branch-service.ts
  分支查询、缓存、请求合并、失效及分支/同步操作

src/renderer/src/lib/git-branches-store.ts
  展示快照、订阅、请求状态及工作区视图
```

调用关系：

```text
更改 / 比较 / Worktree / 侧栏          MR 弹窗
              ↓                        ↓
     分支 Store / 查询入口        CodeHostingService
              ↓ IPC                    ├─ 平台分支缓存
         BranchService                 └─ HostingAdapter
         ├─ 本地 Git 引用
         └─ 分支与同步操作

Git 推送等操作通过明确的失效通知协调对应平台分支资源。
```

职责约束：

- `BranchPicker` 只处理选择、搜索、筛选和键盘交互。
- `SourceControlService` 继续负责文件状态、暂存、提交和 Diff。
- `WorktreeManager` 继续负责授权、绑定验证、生命周期及现有仓库锁。
- `CodeHostingService` 继续负责平台识别、MR 预检、创建和跨重启防重复保护。
- 平台分支缓存归属 `code-hosting`，复用现有适配器；与本地分支资源协调失效，不要求两个数据源由同一个服务管理，避免循环依赖。
- 分支模块不负责整个 Git 模块的所有状态。

## 6. 缓存与请求状态

### 6.1 缓存归属

主进程负责实际数据缓存、失效和请求合并。前端 Store 保存展示快照和订阅状态，不再维护另一套独立 TTL。

资源需要以下状态，具体类型在实施阶段落定：

```text
data        最后一次成功结果
loading     是否正在读取
stale       是否需要重新确认
error       最近一次读取错误
fetchedAt   最后成功读取时间
revision    资源代次
```

主进程内部额外维护当前请求 Promise、失效代次和订阅关系，不向前端暴露内部对象或凭据。

### 6.2 缓存规则

| 数据                       | 缓存与刷新规则                           |
| -------------------------- | ---------------------------------------- |
| 本地分支引用               | 事件驱动失效；没有变化时复用             |
| Worktree 占用关系          | 创建、删除、切换及相关元数据变化时失效   |
| 工作区分支状态             | 复用现有工作区状态，按事件更新           |
| 平台远端分支               | 建议使用 60 秒软过期，并提供手动强制刷新 |
| 账号、权限和写操作前置状态 | 不以列表缓存代替实时校验                 |

“软过期”表示已有结果可以展示，并在有使用方时按需后台更新，不表示每隔 60 秒主动联网。

刷新失败时保留最后成功列表，标记过期、报告错误并允许重试。账号变化和权限失败不适用保留另一账号旧数据的策略，应清理对应平台资源。

分页列表完整读取并通过校验后再作为完整快照发布，不将部分页面标记为完整分支列表；保留现有读取上限和错误处理。

### 6.3 并发与旧结果处理

同一资源、同一有效代次的并发读取共用一次请求。

请求期间发生失效时：

1. 增加失效代次。
2. 旧请求完成后，不得将结果标记为最新。
3. 有活跃使用方时，合并补读一次，避免每个事件都启动读取。
4. 发布前检查资源是否仍为同一缓存条目、工作区绑定是否仍有效。
5. 工作区或缓存已删除时，丢弃迟到响应，禁止复活状态。

强制刷新不能把失效前的在途结果当作最新结果返回。共享请求也不能因某一个组件取消订阅而被其他使用方误取消。

### 6.4 生命周期

- 同仓库共享资源按使用方管理订阅，避免重复创建共享元数据监听。
- 无活跃使用方时停止不必要的后台读取；保留的展示快照应标记为需要重新检查。
- 工作区删除时清理工作区状态；仓库仍有其他使用方时不清理其共享快照。
- 项目关闭且不再被引用、渲染进程退出及应用退出时清理对应缓存、监听和请求发布资格。
- 不持久化分支缓存，不因缓存删除而修改 Git 仓库。

## 7. 刷新与远端同步语义

必须明确区分以下操作：

| 操作           | 含义                               |
| -------------- | ---------------------------------- |
| 刷新列表       | 重读本地 Git 元数据，不联网        |
| 刷新平台分支   | 请求 GitHub/GitLab API             |
| Fetch          | 获取远端提交并更新本地远端跟踪引用 |
| Pull           | 保持现有仅快进策略                 |
| Push / Publish | 保持现有推送及首次设置上游策略     |
| Sync           | 保持现有获取、合并、推送流程       |

普通页面刷新、窗口聚焦和缓存过期不能隐式触发 Git Fetch。

应区分列表读取时间与成功获取远端的时间，不能把“刚读取本地列表”表达为“刚与服务器同步”。无法确定外部 Fetch 对应的远端时，不伪造该远端的精确获取时间。

当前 `--no-prune` 行为保持不变，因此 Fetch 不保证删除服务器已经不存在的跟踪引用。远端引用清理应单独设计，不能顺手改成 `git remote prune`，尤其要保留现有针对自定义 Fetch 映射的安全约束。

## 8. 失效与更新矩阵

| 事件或操作                    | 更新范围                                                         |
| ----------------------------- | ---------------------------------------------------------------- |
| 普通文件修改、暂存、丢弃      | 文件状态，不刷新分支列表                                         |
| Commit                        | 分支引用、当前工作区状态                                         |
| 创建或删除分支                | 仓库分支快照                                                     |
| 切换已有本地分支              | 当前工作区状态、共享 Worktree 占用关系                           |
| 从远端分支签出并创建本地分支  | 本地分支引用、当前工作区状态、上游配置及共享 Worktree 占用关系   |
| Fetch                         | 远端跟踪引用；相关工作区的 ahead / behind                        |
| Pull / Sync                   | 分支引用、工作区状态；部分失败也刷新                             |
| Push / Publish                | 相关引用及上游状态；能够确定对应平台仓库时，使其平台分支缓存失效 |
| Worktree 创建、删除或外部变化 | 分支引用及占用关系                                               |
| Git 配置变化                  | 相关工作区远端、上游及托管上下文                                 |
| CLI 账号变化                  | 对应平台分支缓存、MR 预检结果                                    |
| 工作区或项目删除              | 取消订阅并清理对应状态                                           |

同仓库引用变化后，应使其他 Worktree 的相关数据失效，但只主动刷新有使用方的数据，避免一次 Fetch 导致所有工作区全量扫描。

Sync 执行过推送，以及 Publish 推送成功但设置上游失败时，也应失效能够确定的对应平台分支资源。失效不等于立即联网：没有使用方时只标记过期，不能为定位平台资源额外执行全量账号扫描。平台分支缓存接入前，先保留这一协调边界。

监听在现有实现上扩展：

- 区分工作文件、refs、配置、HEAD 和 Worktree 元数据变化。
- 覆盖共享仓库元数据及不同 Worktree 的 HEAD、占用关系变化。
- 保留事件合并、监听失败后的轮询和恢复机制。
- 用户操作完成后立即刷新相关资源，不等待普通文件状态的三秒节流。
- 窗口隐藏时暂停后台读取，恢复时检查过期状态。
- 不将监听降级轮询扩展成平台 API 或 Git Fetch 定时任务。

## 9. 写操作与并发锁

### 9.1 复用现有仓库锁

继续复用 `WorktreeManager.withRepositoryLock()`，协调：

- 分支写操作。
- Fetch、Pull、Push、Sync。
- Worktree 创建、删除。

不新增第二套分支锁；已经持有仓库锁的内部调用不得再次获取同一把锁，避免嵌套死锁。

### 9.2 分阶段缩短只读网络请求持锁时间

第一阶段不改变锁语义。

后续只针对只读平台请求采用以下流程：

```text
短锁内验证工作区并读取上下文
              ↓
释放锁，执行平台网络读取
              ↓
发布前检查绑定和请求代次
```

Git 写操作和 MR 创建不随之放开。它们涉及本地变更、工作区删除及防重复记录，不能仅为减少排队而移除保护。

已有列表从前端快照展示，无需等待当前网络操作结束才能查看和搜索。修改操作继续受当前操作状态约束。

### 9.3 缓存不得替代实时安全判断

迁移时必须区分“展示查询”与“写操作校验查询”，不能把原本用于校验的 `references()` 无差别替换成缓存读取。

创建、切换、删除和同步操作仍实时验证：

- 工作区授权、绑定与真实目录。
- 仓库身份。
- HEAD、分支和上游。
- Worktree 占用。
- 远端及推送地址。
- 未合并分支、冲突、覆盖和其他 Git 拒绝条件。

保持现有不强推、不自动 stash、不强删未合并分支及明确引用范围等安全语义。

操作失败也可能已经产生部分变更。失效与刷新放在操作收尾路径中，不以成功为唯一触发条件，且不能用刷新成功掩盖原始操作失败。

## 10. MR 弹窗接入

目标流程：

```text
立即打开弹窗
      ↓
实时确认账号、仓库
      ↓
有匹配缓存：展示分支列表，按需后台更新
无缓存：读取平台分支
      ↓
按表单选择的源/目标分支执行预检
      ↓
预检通过后允许创建
```

必须保留：

- 源分支和目标分支均可修改，不绑定本地当前分支。
- 预检、默认文案和创建基于实际表单选择。
- 数据就绪即可填写，预检未通过前禁止创建。
- 后台刷新不覆盖用户草稿，不自动更换源或目标分支。
- 已选分支消失时明确提示，不静默选择替代项。
- 分支切换后的旧预检结果不能启用新分支组合的创建按钮。
- 创建时重新读取远端状态、验证账号和仓库。
- 失败保留输入，跨重启防重复保护不变。

账号验证与分支列表缓存是两个不同问题，不能为弹窗瞬开而跳过账号检查。

加载反馈沿用项目现有规则：200ms 内完成不显示；真正显示后至少保留 300ms，不统一延迟所有请求。

## 11. 渐进迁移步骤

### 阶段一：分支查询与缓存（已实施）

1. 拆分 `GitReferences` 中共享和工作区相关的数据。
2. 建立分支契约和主进程分支服务。
3. 实现缓存、请求合并、失效代次和前端展示快照。
4. 接入现有监听与写操作收尾，先保守失效；覆盖 Commit、分支与同步操作的成功、失败和部分成功，以及 Worktree 生命周期。不能等操作代码迁移后才补失效。
5. 同阶段完成取消订阅、项目关闭、工作区删除、渲染进程退出及迟到响应保护；同仓库其他工作区仍可使用共享资源。
6. 迁移更改、比较两个分支入口，解除对 `session.refreshed` 的分支数组读取依赖。
7. 暂时保留旧 IPC 作为兼容转发，不保留第二份缓存；用于写操作安全校验的实时查询仍不经过缓存。

本阶段不改变分支写操作和仓库锁语义。缓存读取、失效、补读和清理必须形成完整闭环，才能独立交付；可以暂时保守失效，但不能返回无限期不更新的快照。

已落地：

- 新增 `src/shared/git-branches.ts`、`src/main/git/branch-service.ts` 和 `src/renderer/src/lib/git-branches-store.ts`。按真实公共 Git 目录及目录身份共享引用、OID 和占用快照，远端配置仍按工作区读取；当前分支、HEAD 和上游继续复用原工作区状态。
- 更改与比较通过 `SourceControlPanel` 消费分支 Store，不再由 `session.refreshed` 触发分支数组读取。旧 `git:references` IPC 转发到同一资源；`SourceControlService.references()` 仍是写操作校验使用的实时读取。
- 监听元数据失效与普通文件通知分开；补充公共 `worktrees` 元数据监听。窗口恢复、监听重建及降级轮询只重读本地数据，不执行 Fetch。
- Git 分支/提交/同步和 Worktree 生命周期操作的收尾先保守失效全部活跃仓库；普通暂存、取消暂存和丢弃不主动失效分支列表。细分到目标仓库及共享监听去重留在阶段二。
- 已接通订阅释放、布局绑定变更、工作区/项目删除和渲染进程/应用退出清理。刷新失败保留最后成功展示，绑定或仓库身份失效则停止展示旧资源；退订后不接受迟到响应。
- 2026-10-29 验证：主进程和渲染进程 TypeScript 检查通过；一次定向 Vitest 执行中 5 个相关用例通过，覆盖共享读取、配置隔离、失效竞态、退订、监听及原有分支/同步安全行为。未进行 GUI 验证、真实平台写入或性能测量。

### 阶段二：监听与其他使用方（已实施）

1. 在阶段一已区分普通文件和元数据的基础上，继续细分 refs、配置、HEAD 和 Worktree 变更，将写后失效收窄到目标仓库，并去重同仓库共享元数据监听；不再依赖 `session.refreshed` 驱动分支资源。
2. 接入 Worktree 创建、侧栏及共享占用信息。
3. 去除各处重复的分支数组和分支轮询。
4. 保留 Worktree 健康检查等职责不同的逻辑，不能因接口相近而全部删除。
5. 将阶段一已完成的订阅清理和旧响应保护覆盖到本阶段新增的所有使用方。

已落地：

- `SourceControlWatches` 按真实监听路径及递归模式共享原生监听，按公共 Git 目录合并 refs、配置、HEAD、Worktree 和未知变更；普通工作文件与 index 变化不会失效分支列表。配置变化通知使用方重读工作区配置，但复用共享 refs 快照。
- 分支服务自行持有共享元数据订阅，侧栏和 Worktree 创建不依赖 Git 面板打开；最后一个使用方退出时释放监听。Git 面板文件监听复用同一监听引擎，不重复建立公共目录监听。
- 项目级查询通过 `withProjectTarget()` 授权并复用仓库锁，工作区查询仍通过 `withTerminalTarget()`，当前分支直接复用原工作区状态。侧栏只保留打开项目的独立 Worktree 健康检查，不再轮询分支数组，也不为关闭项目的历史登记保留分支订阅；Worktree 弹窗不再独立读取分支与当前分支。
- 展示 Store 统一处理聚焦、隐藏/恢复及监听降级：正常情况下每分钟只进行本地漏事件恢复检查，监听不可用时五秒重试，同仓库恢复只强制读取一份共享 refs。没有平台 API 轮询或隐式 Fetch。
- 写后及布局变更的失效范围已收窄到相关仓库/项目，不再保守刷新所有活跃仓库。

### 阶段三：分支与同步操作（已实施）

1. 将分支操作及 `mutateRemote()` 迁入分支服务。
2. 文件、暂存、提交和 Diff 操作留在原服务。
3. 统一操作状态、错误以及成功、失败、部分成功后的失效与刷新。
4. 保留现有 Git 命令参数和实时校验，避免重构同时改变同步策略。

已落地：

- 分支创建、创建并切换、签出、删除以及 Fetch/Pull/Push/Publish/Sync 的实现迁入 `branch-service.ts`，生产 IPC 分派到 `BranchService.mutate()`。同一把仓库锁在外层授权入口持有，服务内部不重复获取。
- 分支操作的实时状态、引用、占用、远端及推送地址校验和 Git 参数保持不变；成功、失败和部分成功均在收尾使对应仓库快照失效。文件、暂存、提交、Diff 仍由 `SourceControlService` 负责。
- 共享提交解析和错误解释移入 Git runner；原 `SourceControlService.mutate()` 的直接调用保持轻量转发，复用同一份分支操作实现，不存在第二份命令逻辑或缓存。
- 推送请求结束时按已经验证过的推送 URL 通知平台分支资源失效，不额外扫描 CLI 账号；Publish 后续上游设置失败也不会漏掉该通知。

## 12. 验收与验证

### 12.1 行为验收

1. 同仓库多个 Worktree 并发查询，只发生一轮共享 refs 读取，不重复全量查询。
2. 普通文件修改不触发分支列表全量读取。
3. 各 Worktree 的当前分支、HEAD 和上游不会相互覆盖。
4. 外部终端创建、删除分支后，活跃页面能够更新。
5. 请求期间发生失效，旧响应不能覆盖新快照或被标记为最新。
6. 刷新失败保留最后成功列表；账号切换不复用其他账号的平台分支数据。
7. Pull / Sync 部分失败后，界面反映已经完成的部分，并保留原始错误。
8. 删除工作区后，迟到响应不能复活状态；共享资源不影响其他仍在使用的工作区。
9. 写操作保持现有保护，MR 预检与创建不会因缓存绕过校验或重复创建。
10. 手动刷新本地列表不触发 Git Fetch，后台生命周期不产生意外联网同步。

### 12.2 验证方式

- 优先复用现有 `tests/git.test.ts` 中分支、远端同步、Worktree 占用、监听及 MR 保护用例。
- 请求合并、失效竞态和权限隔离等关键逻辑确需回归验证时，再增加最小必要断言或用例，不以覆盖率为目标。
- 实施时按阶段仅执行直接相关测试，遵守项目测试预算，不主动执行全量、E2E 或覆盖率测试。
- 本机测量分别记录冷缓存、热缓存的读取次数、排队时间和请求耗时，不混成单个平均值。
- MR 相关验证默认只读，不实际创建真实 MR，不因验证执行推送、删除或清理远端引用。

## 13. 限制与实施注意事项

- 缓存不能消除首次联网和实时权限校验的耗时。
- 本地远端跟踪引用不具备服务器强实时性，不能用缓存刷新时间掩盖这一点。
- 外部 CLI 修改账号不一定有即时事件；使用平台资源前需实时确认账号、仓库，授权失败应清理对应资源。
- 保留现有 CLI、Git 超时与限流处理，不新增无限重试或后台联网循环。
- 重构期间不得并存两套独立分支缓存、写操作锁或互相竞争的当前分支状态。
- 本文中的实施范围以第 11 节进度为准；具体契约名称和内部类型可在实施时调整，但数据隔离、安全边界及同步语义不得因此弱化。
