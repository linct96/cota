# V0 技术方案

## 已逐项确认的选型

| 范围          | 决定                                                                                                |
| ------------- | --------------------------------------------------------------------------------------------------- |
| 桌面 / 语言   | Electron + TypeScript；首发 macOS Apple Silicon                                                     |
| UI            | React；Tailwind CSS + shadcn/ui（Base UI 基础控件，Mira 风格）                                      |
| 构建 / 包管理 | electron-vite + pnpm                                                                                |
| 终端          | xterm.js + FitAddon；独立 Terminal Host 持有 node-pty，headless xterm + SerializeAddon 保留有界屏幕 |
| 状态          | Zustand；工作区和选中状态持久化，Host 存活时可重接原会话                                            |
| 持久化        | 本地 JSON；后续阶段再引入 SQLite，本期不预建数据库层                                                |
| 打包          | electron-builder，`.app` / `.dmg`                                                                   |
| 测试          | Vitest，仅主线流程与核心逻辑；UI 与原生能力补人工验收                                               |
| 质量工具      | 用户指定 **oxlint + oxfmt**，不使用 ESLint / Prettier                                               |

当前锁定 Electron 44.8.0 / node-pty 1.1.0，其他依赖实际版本见 `pnpm-lock.yaml`。不引入新语言运行时、路由库、tmux 或 Agent SDK；独立 Host 复用现有 Electron / TypeScript。

## 边界与数据流

```text
React / Zustand / xterm.js
         │ window.desktop（固定接口，不暴露 ipcRenderer）
Sandboxed Preload / contextBridge
         │ 类型化 IPC；请求携带 terminal ID，不携带任意命令执行能力
Main：来源校验 + 参数校验
         ├── ConfigStore：JSON、最近项目、偏好、工作区 / 标签关联 / 选中状态
         └── HostClient：带随机凭据的本地 Unix socket
                    └── 独立 Terminal Host：TerminalManager + 有界 headless 屏幕
                              └── 交互式登录 Shell → 用户自行运行的 CLI
```

终端输入当然可由用户执行 Shell 命令；“无任意命令执行 API”指 Renderer 没有绕过该终端会话的 Node / shell / 文件系统通用能力。IPC 创建终端仅接受已打开项目，Shell 来自校验后的本地设置。

- PTY 创建前保留资源槽位，避免并发突破 10 标签限制；失败释放槽位。
- 输出按短时间窗口批量发送，累计未渲染字符达到高水位时暂停读取，xterm 处理回调通过 ACK 释放流控。关闭后到达的布局 resize 安静忽略，实际写入已退出会话仍拒绝。
- 工作区在 Renderer 内按项目组织；名称、UUID、终端关联、活动标签及选中状态通过 `workspace:save-layout` 保存到现有 JSON 配置。启动复用 `currentWorkspace` 从保存的项目与工作区映射中定位上次工作区，仅当该工作区有 Host 实际返回的终端时恢复 `selectedProject` 与活动标签，否则保持未选中；不因其他工作区存在终端而改选或激活空工作区。正常 `Cmd+Q` 清理后不恢复选中；升级重启等场景若 Host 会话保留则恢复。保留命名工作区及活动标签，不自动创建终端；原活动标签缺失时使用该工作区的其他现有标签。启动向 Host 查询实际存在的会话，只恢复仍存活的 Shell / 已退出屏幕，丢弃不再存在的旧标签，不重新执行旧命令。添加项目时默认创建一个工作区，所有工作区平等且均使用独立 UUID。终端创建 IPC 携带 `workspaceId`，Main 的会话同时记录项目路径和工作区 ID；各工作区分别保存活动标签，快捷键与标签列表只操作当前工作区。点击工作区调用 `selectProject(path, workspaceId)`，目录验证及选中成功后，若目标没有终端则复用 `newTerminal()` 自动创建（遵守全局上限，重复点击不重复创建）。`closeTab` 仅在 Main 确认关闭成功、目标已无标签且仍是当前工作区时清空 `selectedProject`，取消工作区选中但保留项目与工作区记录；等待关闭期间若已切换到其他工作区，则不影响新选中项。取消或关闭失败保持选中状态。所有工作区仍共用项目目录与全局 10 终端上限。`workspace:remove` 仅关闭目标工作区的 PTY；删除最后一个工作区时通过 `removeProject` 标记一并移除最近项目记录，成功后 Renderer 移除文件夹行。配置新增可选 `layout` 字段，兼容既有无布局的配置；仅持久化身份与界面状态，不持久化进程或终端输出。
- Git 分支副标题通过只读 `project:branch` IPC 获取；Main 校验目录后以 `execFile` 执行固定参数 `git symbolic-ref --quiet --short HEAD`（2 秒超时、4 KiB 输出上限），不经 Shell。Renderer 按项目路径去重，首次加载、窗口聚焦及可见时每 5 秒刷新，丢弃已移除项目的在途结果；同目录工作区共用分支信息，不持久化。非仓库、分离 HEAD、Git 缺失或目录不可访问时隐藏副标题，不阻碍工作区使用。
- 非当前项目、工作区及标签的 TerminalView 保持挂载；ResizeObserver 和重新激活时的 fit 向 PTY 同步字符尺寸。关闭设置或重新选择标签后恢复终端焦点。
- 禁用后台节流，避免窗口被遮挡时终端处理依赖前台帧率。
- 当前只提供 ChatGPT 风格的浅色主题，不跟随系统深色外观，也不提供主题切换；CSS 控件、Main 原生外观及 xterm 背景 / ANSI 调色板一并适配，终端设置最低文本对比度 4.5。
- 标题栏由 Renderer 绘制，Main 使用 `titleBarStyle: hidden` 保留 macOS 原生红黄绿按钮；48px 高标题栏预留按钮空间，直接容纳终端标签、新建终端及设置，不展示 Cota 标题；空白区域可拖动，标签列表和交互控件使用 `no-drag`。最左侧 52px 图标导航栏目前仅展示已选中的首页，不新增其他页面。
- 关闭终端标签（含 `Cmd+W`）先通过 Host 的 `needsCloseConfirmation` 检查 PTY：已退出直接关闭；存活会话通过 `/bin/ps -axo pid=,ppid=,stat=,comm=`（2 秒超时、4 MiB 上限）判断是否有子进程（含后台/暂停任务，排除 `stat` 含 `Z` 的已结束僵尸进程），以及根进程名称是否不同于创建时的 Shell（覆盖 `exec` 替换）。仅确认空闲时跳过弹窗；检测失败保守要求确认。检测/关闭期间拒绝目标终端的新输入，避免用户在检测后启动任务。纯 Shell 内建计算、无子进程的情况无法精确判断，需 Shell integration 才能覆盖。关闭窗口及退出应用（含 `Cmd+Q`）仍按是否有存活 PTY 决定确认，不套用空闲豁免。需要确认时统一由 Main 通过带唯一 ID 的 `app:confirm` 事件请求 Renderer 的 shadcn AlertDialog（Base UI / Mira）；默认聚焦取消，Escape 取消，回复通过 `app:confirm-response` 校验窗口来源、请求 ID 和布尔值，过期或重复回复拒绝。等待期间保留关闭/退出排他锁；Renderer 重载、崩溃或销毁时取消在途确认，不结束进程。已退出终端直接关闭，无存活终端直接退出；退出清理失败使用相同组件提示并保留应用。先清理进程，再移除标签或退出。进程树快照包含前台进程组中的子进程，先 HUP、等待，再 KILL。不能承诺捕获已脱离管理树的守护进程。
- 文件夹行保留点击展开/收起，不显示展开箭头；右侧提供新建工作区和三点菜单；新建先打开 shadcn Dialog（Base UI / Mira），预填并选中“工作区 N”，确认后才调用 `newWorkspace(path, name)` 创建并选中，成功才展开文件夹。名称去除首尾空格后不能为空，自动编号仅统计“工作区 数字”格式，避免自定义名称污染编号；取消不改变状态，提交中禁止关闭和重复提交，失败保留输入并显示错误供重试。菜单的“删除项目”调用 `project:remove`，按项目关闭全部 PTY、清理全部工作区并调用 `ConfigStore.forget`。工作区行不显示三点按钮；右键菜单的“编辑工作区”复用命名 Dialog，预填并选中原名称，保存调用 `renameWorkspace(id, name)`，仅更新名称、不切换工作区或操作终端，拒绝空白名称、已删除目标及删除期间的修改；取消不改变状态。右键菜单的“删除工作区”调用 `workspace:remove`。两种删除共享 Main 排他锁并等待在途创建；Renderer 共用 shadcn AlertDialog（Base UI / Mira），默认聚焦“取消”，支持 Escape 取消，执行期间禁止关闭或重复提交。删除仅移除 Cota 记录，不操作项目文件；入口校验项目绝对路径及工作区 UUID，不要求目录仍存在。成功才移除 Renderer 中的标签和记录；删除期间阻止目标创建和退出竞态，Renderer 同时禁用项目切换、新建及关闭。清理或落盘失败保留目标记录供重试并记录控制台错误，已终止进程不承诺恢复。
- Renderer 不维护全局 `error` / `report`，不显示 `workspace-error` 横幅。项目操作、资源上限、布局保存及终端写入/调整尺寸失败仅记录到开发者控制台；启动警告同样记录日志，加载失败不覆盖已有布局。保留终端自身错误状态、设置/工作区命名表单及退出确认弹窗内部的错误提示。
- 配置串行更新、原子替换，损坏时保留原文件并阻止覆盖。单实例锁避免同一应用并行写入；不引入跨外部编辑器的分布式锁。
- 非打包运行（含 `pnpm dev` / `pnpm start`）使用名称 `Cota Dev`，在单实例锁及 `ready` 前创建并设置独立的 `appData/Cota Dev` 为 `userData` / `sessionData`；macOS 默认为 `~/Library/Application Support/Cota Dev`。正式版路径不变。配置、缓存、单实例锁及按 userData 派生的 Host / PTY 会话独立，可同时运行；不迁移原有配置。项目文件、Shell 初始化文件及外部 CLI 配置仍属于同一系统用户，不做沙箱隔离。
- 禁止页面导航、弹出窗口、额外权限；CSP 约束本地 UI。生产默认不开调试端口；开发/验收时才通过启动参数启用。

## Terminal Host 与重连边界

- `host-entry.ts` 是单独构建入口，使用当前 Electron 的 Node 模式 detached 启动；普通窗口关闭 / Quit 仍先清理全部终端并关闭 Host。Renderer 重载只 detach；Main 意外退出导致 socket 关闭时，Host 保留会话供下次启动接回。更新器、签名稳定 Helper 和跨版本迁移不在本次范围。
- 每个 userData 对应独立短路径 socket 目录，权限 `0700`；随机 token 元数据及 socket 为 `0600`。握手校验 token / 协议版本；超时、权限不明、活 PID 暂不可连接均不视为死亡，不终止或覆盖未知端点。同一应用的单实例锁串行化启动。
- `create` 使用稳定 ID 幂等创建；`attach` 仅接已有会话，缺失即报错，不静默创建。每次视图附着使用独立 UUID，旧视图的 detach / ACK 不得影响新视图；Renderer 卸载后到达的 attach 也会释放。
- Host 用 headless xterm 保存有界普通 / alternate screen。attach 排在解析队列的屏障上取快照；快照之前的输出不重播，之后解析的输出发送给新视图，避免快照与实时输出之间丢失或重复。客户端恢复快照前禁止输入 / resize，并暂存实时事件；恢复后再 fit 到真实窗口尺寸。当前序列化不保留未完成的转义序列解析状态，不承诺任意复杂终端协议无损恢复。
- 有界输出与解析队列均参与背压，切断视图会释放其 ACK 债务；无客户端时继续解析输出，按 scrollback 上限保留屏幕并回答必要的终端状态查询，不因 Renderer 消失而卡住 Shell。scrollback 设置同时同步到 Host 与 Renderer。
- 启动以 Host 实际会话为准合并磁盘布局；在途创建先在 Host 中保留槽位并等待完成后列出。若进程存在但布局写入前 Main 已退出，按 Host 记录重建关联；尚存会话的项目即使曾被最近项目上限挤出，也重新纳入列表。Host 死亡 / 系统重启后不做冷恢复、不保存磁盘历史。

## 目录

```text
src/main/                 配置、Shell、校验、Host 客户端 / 服务端、PTY 和应用生命周期
src/preload/index.ts      固定 IPC 桥及可释放的事件订阅
src/shared/contracts.ts   跨进程类型、默认值、资源限制
src/renderer/src/         App、Zustand store、终端与设置
src/renderer/src/components/ui/  shadcn/ui 基础控件
scripts/pty-smoke.cjs      Electron ABI 下的真实 Shell 检查
scripts/host-smoke.cjs     构建 / 打包版 Host 脱离父进程、原 PID 重连、TUI 快照与背压检查
tests/                    工作区状态、配置、校验、IPC、PTY 生命周期、进程树、Git 逻辑测试
```

自动化测试保留业务状态转换、安全校验、并发互斥、异步竞态和失败恢复；不覆盖 DOM 结构、样式、文案、菜单焦点及弹窗交互，不重复测试 Base UI 基础组件行为。Renderer store 在 Node 环境中通过 mock DesktopAPI 测试，无需渲染 React；界面行为由人工回归验收。历史验收记录保留当时的测试范围，不代表当前测试清单。

仅重接仍由同一 Host 托管的进程，不在 Host 已死时重新运行命令；不保存完整终端输出，不分析 Agent 内容，不引入远程、多代 Host、更新器等扩展。发布仍受 [验收记录](验收记录.md) 中尚未完成的人工验证约束。
