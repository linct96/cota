## 发现与修复

首轮 Pi 状态可用，但 Codex / Claude 的任务事件均未进入状态引擎。临时只读元数据探针确认：原生 Hooks 通过独立会话 / 进程组的 shell 启动，其 `pgid` 不同于 PTY 前台 Agent；旧 `agentOwner` 拒绝了这条合法祖先链。此前 mock 将辅助进程建模为与前台同组，未暴露该问题。

修复仅允许**菜单直接启动且仍占据前台的 Agent 根进程**拥有这类 detached Hook 辅助进程；仍校验终端凭证、provider、完整祖先链、根进程前台状态、PID / 启动时间。普通 Shell 不获得该例外，后台 / 无关进程仍被拒绝。修复后用新的隔离环境复验，Codex 和 Claude 状态接入恢复。探针已由重新构建移除，不进入源码或交付物。

## 跨会话验证

- 两个真实 Git Worktree 分别运行 Pi、Codex，`pwd` 与绑定 cwd 相符；另有 Claude 和 Shell 会话同时存活，状态不串线。
- Host 客户端断开重连两次，终端 ID、launchId 与状态快照保持一致；没有重新创建 Agent。
- Shell 中 Pi → 退出 → Codex → 退出，动态 launchId 更换，revision 递增，PTY 保留。
- 使用空的 Pi 配置目录启动时，仅识别为 `process/unknown/unavailable`，没有安装 Cota 扩展。该负向场景未覆盖 Codex / Claude。
- 原生授权标记文件在批准前不存在，批准后内容为预期值；取消授权的目标文件始终不存在。
- 对采集的白名单状态及上述文件门禁执行 assert 检查通过。只保存状态元数据，不将任务内容加入验收记录。
