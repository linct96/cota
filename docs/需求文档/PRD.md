# ADE V0 产品需求文档（PRD）

> 文档编号：ADE-V0-PRD  
> 版本：1.0（需求冻结草案）  
> 日期：2026-10-16  
> 面向：产品负责人、开发人员、AI 编程代理  
> 产品代号：ADE（最终名称待定）

## 1. 产品概述

### 1.1 一句话定位

ADE V0 是一款 **macOS 优先的本地 Terminal-first 开发工具**：用户打开本地目录，在内置交互式终端中自行运行已经安装的 `codex`、`pi`、`claude` 等 CLI 工具。

ADE **不是**新的 Agent 模型运行时，不管理 Agent Prompt，不解析其私有协议，也不替代 CLI 自身的登录、权限确认与更新机制。

### 1.2 目标用户

- 已有 macOS 开发环境的个人开发者；
- 已通过命令行安装并使用 Codex CLI、Pi 或 Claude Code 的开发者；
- 想在同一个桌面应用中管理多个项目及多个终端的人。

### 1.3 核心问题

用户需要频繁在文件夹、终端窗口和 Agent CLI 之间切换。ADE V0 希望把“项目选择 + 终端管理”集中到一个轻量桌面应用中，而不增加额外的 Agent 配置负担。

### 1.4 V0 成功标准

一个已安装 `codex` / `pi` / `claude` 的 macOS 用户，能够：

1. 启动 ADE，选择一个本地项目目录；
2. 在该目录创建终端，交互式运行任意一个已安装的 CLI；
3. 打开第二个终端并在标签之间切换，两个终端的进程继续正常运行；
4. 关闭终端时获得明确提示，并正确清理对应进程；
5. 正常退出后再次启动，恢复最近项目和命名工作区，保持工作区未选中，点击后才激活，不重新执行旧命令；若只是 Main 意外结束且独立 Host 仍存活，则接回原终端。

**“支持 Codex/Pi/Claude”仅表示支持用户自行启动和使用它们的 CLI。** 不保证这三个 CLI 所有未来的私有终端功能均获得特殊适配。

## 2. 版本范围

### 2.1 V0 包含

- macOS 本地桌面应用（首发 Apple Silicon）；
- 单应用主窗口；
- 打开与切换本地文件夹（无需是 Git 仓库）；
- 最近项目列表（持久化）；
- 每个项目多个 Terminal Tab；持久化工作区身份、名称、标签关联与选中状态；
- 本地独立 Terminal Host；Renderer / Main 重载或意外结束后，可重接仍存活的原终端与有界屏幕。
- 交互式 PTY：键盘输入、输出、ANSI、TUI、调整尺寸、复制与粘贴；
- 默认 Shell 与自定义 Shell 路径设置，优先支持 zsh / fish / bash；
- 显式终端关闭与应用退出清理；
- 本地 `.app` / `.dmg` 构建、基础测试和使用说明。

### 2.2 明确不包含（禁止 AI 自行添加）

- Pi SDK 原生接入、Codex App Server、Claude Agent SDK；
- 自动发现或识别 CLI Agent 类型、解析 Agent 消息/工具调用/成本；
- Git Worktree、Git Diff、Monaco 编辑器、文件浏览器；
- SQLite、云端同步、远程 SSH、移动端、插件市场；
- 系统 / Host 重启后的进程冷恢复、磁盘终端历史、tmux 自动接管；
- 更新器、跨版本 Host 路由、签名稳定 Helper 打包及安装包替换期间的存活保证；
- 自动安装、登录或升级 Codex/Pi/Claude；
- Agent 编排、定时任务、多用户协作、账户系统；
- 多窗格自由分屏、复杂 Dock、多桌面窗口；
- 收集终端输出或提示词的遥测/云端日志。

> 2026-10-17 经用户明确确认，新增上述本地独立 Host 与工作区持久化；正常退出仍结束终端，不实现后续更新逻辑。其他扩展功能仍需单独确认。

## 3. 需求优先级与清单

优先级说明：**P0 = V0 上线必须完成**，**P1 = V0 之后考虑**。所有 P0 需求必须有测试或手动验收记录。

### 3.1 项目管理（P0）

- [ ] **PRJ-001｜打开目录**：用户通过主界面按钮或 `Cmd+O` 打开 macOS 系统目录选择器。取消选择时不改变现有状态。
  - 验收：可以打开包含中文/空格的路径；可以打开非 Git 目录。
- [ ] **PRJ-002｜项目列表**：左侧栏显示最近打开的项目，包含项目文件夹名和可辨识路径信息；重复打开不产生重复项。
  - 验收：重新打开既有项目后列表只有一项；最近使用项目置顶。
- [ ] **PRJ-003｜项目切换**：选择左侧项目时切换当前显示的 Terminal Tab 列表；其他项目中仍在运行的终端继续工作。
  - 验收：项目 A 中运行的终端在切到项目 B 再切回后仍可输入。
- [ ] **PRJ-004｜持久化最近项目**：退出并重启应用后显示最近打开的项目（建议最多保存 20 项）。
  - 验收：不要求重启后自动重新运行终端。
- [ ] **PRJ-005｜目录失效**：目录被删除、移动或不可访问时拒绝切换并记录控制台错误，不允许基于无效路径启动 PTY，不显示全局错误横幅。
- [ ] **PRJ-006｜删除项目**（2026-10-16 补充）：文件夹行提供“更多操作 → 删除项目”；shadcn 确认弹窗默认聚焦“取消”，说明将删除该项目全部工作区并结束所有终端、丢弃输出，但不会删除本地文件。确认后先清理终端，再持久化移除最近记录；其他项目保持运行。
  - 验收：取消保持原状；删除当前项目后选中剩余项目，无剩余项目则显示空态；失效目录也能移除；重启不再出现已删记录，重新打开仍可添加。删除中避免重复操作与新建竞态；失败保留项目、记录控制台错误并允许重试，已结束终端无法恢复。
- [ ] **PRJ-007｜工作区管理**：添加项目默认创建一个工作区，文件夹行的“+”打开命名弹窗，预填“工作区 N”并选中文本，允许自定义名称，确认后才创建；取消不改变状态，名称去除首尾空格后不能为空，创建失败保留输入并允许重试；每个工作区均以独立 UUID 标识，彼此平等且独立管理终端标签，共用项目目录，不提供文件隔离。工作区标题下方在可获取 Git 分支时展示分支副标题；同项目工作区共用分支信息，切换分支后自动刷新。无分支信息时不展示，不要求目录为 Git 仓库。文件夹名可点击展开/收起，不额外显示展开箭头。
  - 验收：工作区行“右键菜单 → 编辑工作区”可修改名称，预填并选中原名称；名称去除首尾空格后不能为空，保存不改变当前选中状态或终端，取消不生效。“右键菜单 → 删除工作区”仅结束目标工作区的终端并移除该工作区；删除最后一个工作区时自动移除文件夹行和最近项目记录。点击选中空工作区时自动创建一个终端，已有终端则恢复原活动标签，不重复创建，仍遵守全局 10 个终端上限。关闭当前工作区最后一个终端成功后取消该工作区选中，保留其记录，不立即补建终端，再次点击选中时才创建；取消或关闭失败保持原状。切换工作区不终止其他工作区的终端；命名工作区、UUID 和各工作区的活动标签跨应用重启保存，启动仅在上次工作区仍有 Host 实际会话时恢复该工作区和原活动标签，否则保持未选中，不自动新建终端。

### 3.2 终端（P0）

- [ ] **TERM-001｜创建终端**：在当前项目里新建 Terminal Tab，Shell 的初始 `cwd` 必须是该项目目录；支持 `Cmd+T`。
- [ ] **TERM-002｜原生交互**：支持输入、回车、方向键、Backspace、Tab、Ctrl+C、Ctrl+D、ANSI 颜色、Unicode、常见全屏 TUI / alternative screen。
  - 验收：`vim` 或其他常见 TUI 能进入、操作、退出；在已安装时可交互式运行 `codex`、`pi`、`claude`。
- [ ] **TERM-003｜流式输出**：终端持续显示 Shell 输出；较大输出不会冻结整个桌面应用。
- [ ] **TERM-004｜多标签**：一个项目可建多个终端；切换标签不得停止未激活的终端。
  - 验收：终端 A 运行持续输出命令，切换到 B 后 A 继续执行，返回后可查看结果。
- [ ] **TERM-005｜调整尺寸**：窗口变化或标签重新显示时，终端重新计算字符列数/行数并同步给 PTY。
  - 验收：`stty size` 与展示区域相符；全屏 TUI 无明显错位。
- [ ] **TERM-006｜复制粘贴**：macOS `Cmd+C` 复制终端选中文本，`Cmd+V` 向 PTY 粘贴文本；`Ctrl+C` 保留发送 SIGINT 的终端语义。
  - 验收：在 CLI 中粘贴多行文本时遵循终端粘贴行为；选中文本复制不向 CLI 发送中断。
- [ ] **TERM-007｜关闭标签**：关闭终端（含 `Cmd+W`）时，空闲 Shell 或已退出的终端无需确认；存在前台/后台任务（含暂停任务，不计已结束的僵尸进程）、Shell 已被其他程序替换，或进程状态检测失败时，通过 shadcn AlertDialog 明确警告将结束该 Shell 及其中程序，确认后终止对应 PTY。纯 Shell 内建计算且无子进程无法精确识别。
  - 验收：取消关闭不影响运行；确认关闭后对应标签和进程均退出，其他标签不受影响。
- [ ] **TERM-008｜退出反馈**：Shell 自行退出后，Tab 展示 `Exited` 状态及可获得的退出码，不再允许向已退出 PTY 写入。
- [ ] **TERM-009｜合理资源上限**：V0 每次运行最多同时保持 10 个终端，达到上限时不再创建并记录控制台信息，不显示全局错误横幅；每个终端的可见 scrollback 有上限（默认 5,000 行，可配置为 1,000–20,000）。
- [ ] **TERM-010｜终端焦点**：切换标签、选择项目、重新进入终端后，键盘聚焦和输入行为符合预期；中文输入法可正常输入。

### 3.3 Shell 兼容性与设置（P0）

- [ ] **ENV-001｜默认 Shell**：优先使用用户的 `SHELL`（若为可执行的绝对路径），否则回退 `/bin/zsh`。
- [ ] **ENV-002｜交互式登录环境**：使用登录 + 交互式 Shell 语义，支持用户现有的 `PATH`、Homebrew、fnm、fish 等初始化配置。
  - 验收：通过 Finder 启动 ADE 与从 Terminal 启动 ADE，均能运行用户已在系统终端中可运行的 `codex` / `pi` / `claude`（若某种初始化方式不兼容，应提供清晰说明与手动路径配置）。
- [ ] **ENV-003｜Shell 设置**：提供设置界面，允许选择“系统默认”或填写 zsh/fish/bash 可执行文件的绝对路径；输入不合格时给出错误，不执行任意带参数命令字符串。
- [ ] **ENV-004｜CLI 缺失提示**：ADE 不自动安装 CLI；若输入 `codex` 等命令后 Shell 报 `command not found`，用户能看到原始错误，README 提供环境排查方式。

### 3.4 应用生命周期（P0）

- [ ] **LIFE-001｜关闭窗口/退出应用**：当存在存活 PTY 时，关闭主窗口或选择 Quit（含 `Cmd+Q`）必须通过 shadcn AlertDialog 提示终端将结束，默认聚焦“取消”，支持 Escape 取消；取消则继续运行。关闭终端标签按 TERM-007 判断是否需要确认，使用同一通用确认组件；仅关闭标签支持空闲豁免，不改变窗口关闭/退出规则。退出清理失败通过同一组件提示，应用不退出。
- [ ] **LIFE-002｜正常退出清理**：确认退出后按顺序关闭所有 PTY；不得让 ADE 正常退出后仍遗留由 ADE 直接管理的终端 Shell。
- [ ] **LIFE-003｜重启语义**：最近项目、设置和命名工作区恢复；仅当上次工作区仍有 Host 实际会话时恢复该工作区和原活动标签，原活动标签缺失则使用该工作区的其他现有标签，否则保持未选中，不自动创建终端。正常 `Cmd+Q` 清理终端后重开不恢复选中；升级重启等场景若保留 Host 会话则恢复。Renderer 重载、Main 意外退出后，只要 Host 仍存活就接回原 Shell、标签及有界屏幕；attach 缺失或超时不自动重跑命令。正常退出仍结束终端；Host / 系统重启后不冷恢复进程、终端历史或旧标签。复杂终端协议 / 不完整转义序列中途断线不承诺无损恢复。
- [ ] **LIFE-004｜错误处理**：创建 PTY 失败、Shell 路径错误保留终端或设置内部的错误状态；项目操作及布局保存失败记录到开发者控制台，保留现有记录供重试。不显示工作区全局错误横幅，不因异常闪退。

### 3.5 桌面 UI 与交互（P0）

- [ ] **UI-001｜主布局**：左侧项目栏，右侧 Terminal Tab 栏 + 终端工作区；无项目时显示“Open Folder”空态。
- [ ] **UI-002｜快捷键**：`Cmd+O` 打开目录；`Cmd+T` 在当前项目新建终端；`Cmd+W` 关闭当前终端（无终端时按照窗口规则处理）；`Cmd+1…9` 在当前项目切换终端。
- [ ] **UI-003｜浅色主题**：按 2026-10-16 最新确认，第一版采用 ChatGPT 风格的浅色主题，暂不开发深色模式；文本、光标、背景有足够对比度。
- [ ] **UI-004｜状态提示**：Tab 至少显示 Running / Exited；创建中显示加载状态；保留终端及表单内部的异常提示，不显示全局错误横幅。

### 3.6 打包与交付（P0）

- [ ] **REL-001｜开发启动**：提供单条启动命令 `pnpm dev`，README 写明 macOS、Node、pnpm 等要求。
- [ ] **REL-002｜质量检查**：提供 `pnpm typecheck`、`pnpm test`、`pnpm build`；命令应可在未配置 Agent 账号的机器上执行。
- [ ] **REL-003｜本地构建**：在 Apple Silicon macOS 上输出可启动的 `.app`；尽量同时输出供个人安装使用的 `.dmg`。
- [ ] **REL-004｜原生模块验证**：打包后 `node-pty` 能加载，创建终端并运行交互式 Shell。仅开发模式可用不算交付完成。
- [ ] **REL-005｜发行说明**：注明 V0 可为未签名开发构建；如未完成签名与公证，明确说明系统安全提示，不把未签名包描述为正式可公开分发版本。

## 4. 界面信息架构

```text
┌───────────────────────────────────────────────────────────┐
│ ADE                                         Settings      │
├────────────────┬──────────────────────────────────────────┤
│ PROJECTS       │ [Terminal 1] [Terminal 2] [+]            │
│                ├──────────────────────────────────────────┤
│ > my-app       │ ~/projects/my-app %                      │
│   api-server   │                                          │
│                │ $ codex / pi / claude                     │
│ + Open Folder  │                                          │
│                │               interactive PTY            │
└────────────────┴──────────────────────────────────────────┘
```

规则：

- 左侧项目是持久的“最近项目”，并不是项目资源管理器；
- 同一进程内切换项目时，其终端留在内存并继续运行；
- 不同项目终端相互独立，始终固定在创建时的 `cwd`；
- 关闭终端必须明确清理 PTY；隐藏终端不能视作关闭。

## 5. 关键用户流程

### 流程 A：首次运行

启动 ADE → 无项目空态 → 点击 Open Folder → 系统选择目录 → 项目进入侧边栏并选中 → 点击 New Terminal → Shell 在项目目录启动 → 用户运行 `codex` / `pi` / `claude`。

### 流程 B：多终端协作

打开项目 → Terminal 1 运行 `pi` → `Cmd+T` 创建 Terminal 2 → Terminal 2 运行 `codex` → 切回 Terminal 1 → Terminal 1 的进程和会话继续工作。

**说明：V0 多终端不提供文件写入隔离；两套 CLI 在同一目录修改相同文件可能产生冲突，须由用户自行协调。**

### 流程 C：退出

应用仍有存活终端 → 用户点击关闭窗口或 Quit → 显示将停止终端的提示 → 用户确认 → 清理 PTY → 退出应用。取消则保持原状。

### 流程 D：重启

重新启动 ADE → 恢复最近项目和命名工作区，不自动新建终端 → 若上次工作区仍有 Host 实际会话，接回原会话及屏幕并激活原工作区和活动标签；否则保持工作区未选中 → 空工作区需用户点击后才创建新终端，不自动重新执行旧 CLI 命令。正常 `Cmd+Q` 后无旧会话，不恢复选中；升级重启等保留 Host 会话的场景按此规则恢复。

## 6. 非功能性要求

- **可靠性**：单个终端异常退出不得导致其余终端退出；正常关闭后不遗留直接管理的 Shell。
- **响应性**：项目选择、切换标签、输入和滚动应保持可交互；大段输出须分批更新 UI。
- **安全性**：Renderer 不允许直接访问 Node.js、文件系统或任意命令执行 API；Main 校验来源与参数，通过认证的本地 socket 访问独占 PTY 的 Host。
- **隐私**：终端输出默认仅在内存中供呈现，不写入完整日志或上传服务器；最近项目路径保存在本地。
- **可维护性**：IPC 契约类型化，PTY 实例有单一所有者，事件订阅必须在卸载时释放。
- **兼容性**：以 macOS Apple Silicon、zsh/fish/bash 为初始测试矩阵；不承诺完全等同系统 Terminal 的全部控制序列。

## 7. Release Gate / 最终验收

V0 必须至少通过以下真实测试（由 AI 记录 Pass/Fail 与证据）：

| 编号 | 场景 | 预期结果 |
|---|---|---|
| A01 | 打开含空格和中文的目录 | PTY `pwd` 指向正确目录 |
| A02 | 打开非 Git 目录 | 允许创建终端 |
| A03 | 在不同项目分别建终端 | 两个 `pwd` 不同，切换后状态正确 |
| A04 | 在 A 执行持续输出命令，切到 B 再返回 | A 进程持续运行 |
| A05 | `Ctrl+C` 中断前台命令 | 程序按正常 Shell 行为中断 |
| A06 | `Cmd+C` 复制已选择的文本 | 剪贴板内容正确，CLI 未被中断 |
| A07 | `Cmd+V` 粘贴中文与多行文本 | 内容正确输入到终端 |
| A08 | 窗口 resize；运行常见全屏 TUI | 尺寸同步，画面不明显损坏 |
| A09 | Finder 启动，输入已安装 CLI 名称 | CLI 可正常找到；不行则明确报错及排查 |
| A10 | 关闭存活 Tab 后取消 | PTY 不受影响 |
| A11 | 确认关闭存活 Tab | 对应 PTY 关闭，其他 Tab 保持运行 |
| A12 | 正常退出后重启；保留 Host 会话时重开 | 项目和命名工作区保留；正常退出清理终端后不选中工作区、不重跑旧终端；上次工作区仍有 Host 会话时恢复原工作区、活动终端和屏幕 |
| A13 | 打包 `.app` 启动并输入 Shell 命令 | `node-pty` 实际可工作 |
| A14 | 项目目录被移走或 Shell 路径无效 | 失效目录拒绝切换并记录控制台错误；Shell 错误在终端或设置内展示，无应用崩溃 |
| A15 | 终端中运行 `codex`、`pi`、`claude`（若机器已安装且已认证） | 支持交互式输入/输出；未安装则标为环境不具备，不伪造通过 |

> A15 为人工集成测试，不应在 CI 中要求第三方 Agent 凭据，也不能以模拟输出替代真实 CLI 测试。

## 8. 交付定义（Definition of Done）

全部 P0 需求完成；执行 `typecheck/test/build` 成功；A01–A14 有明确测试结论；A15 在可用环境下实测；在 Apple Silicon macOS 打包后的应用验证过真实 PTY；README 包含启动、构建、Shell 问题排查、退出语义与已知限制。

## 9. 变更控制

需求冻结原则：编码 AI 不得将 P1 项目“顺手”纳入 V0；涉及数据库、Agent SDK、云端、Daemon 或新语言运行时的架构改变需先提交简短 ADR 并获得明确同意。
