# 开发环境

在项目目录运行 `pnpm dev`（首次先执行 `pnpm install`），可与已安装的正式版同时运行。

- 开发版名称为 **Cota Dev**，数据目录为 `~/Library/Application Support/Cota Dev`；正式版继续使用原有数据目录。
- 配置、最近项目、工作区、缓存、单实例锁及 Terminal Host / 终端会话互相独立；退出任一版本不会清理另一版本的终端。
- 开发版首次使用独立的空白配置，不自动复制或迁移原有配置。
- 两边若打开同一个项目目录，仍会操作同一份文件；Shell 配置和外部 CLI 的账号等也不隔离。

## 终端渲染

在 **设置 → 终端 → 渲染** 中选择 **GPU 加速**，默认「自动」。设置即时保存并作用于现有终端，不重启 Shell、不清空输出，仅影响终端 WebGL 渲染，不改变 Electron 全局硬件加速。

- **自动**：可见终端优先尝试 WebGL；初始化失败或上下文丢失且无法恢复时回退 DOM，本次界面运行不再自动尝试。
- **开启**：忽略自动模式的失败记录，显式尝试 WebGL；仍失败时安全回退，可切换「关闭 → 开启」重试。
- **关闭**：使用 DOM 渲染。隐藏终端释放 WebGL 插件，重新显示时按当前选项加载，不影响后台进程和输出缓冲。
- 尚未保存此选项的配置使用「自动」；硬件或驱动不支持时，「开启」也不保证实际使用 GPU。

## Git Worktree 工作区

项目菜单可分别创建逻辑 Local 工作区或独立 Git Worktree。Worktree 从本地基础引用新建分支，目录由 Cota 管理，正式版新目录位于 `~/.cota/worktrees/<仓库名>/<工作区名>`，开发版位于 `~/.cota-dev/worktrees/<仓库名>/<工作区名>`，如 `cota/fix-login`；同名仓库追加短标识，工作区目录被占用或该仓库曾使用过时依次追加 `-2`、`-3`，不会覆盖或复用旧目录。内部完整 ID 保留；每个工作区的终端在其真实目录启动，只打开普通 Shell，不自动运行 Agent。

- 新建 Worktree 只需一个名称输入框，默认随机太空名称（行星、卫星、恒星、星座和星系，如 `mars`、`titan`、`vega`）；可直接创建，也可自定义修改。分支自动为 `<Git 用户名称>/<工作区名称>`，如 `linct96/mars`，修改名称会同步更新分支名；基础引用默认选中并显示当前分支名称，不额外列出 `HEAD`；Detached HEAD 时显示并默认选择 `HEAD（当前提交）`，也可通过下拉修改，弹窗不展示分支名和目录。Git 用户名称读取仓库生效的 `user.name`（需提前配置），分支各段统一小写、空格及其他不安全字符替换为连字符。Local 工作区命名不变；名称池耗尽后进入 `mars-2` 等下一轮。
- 默认名称避开当前登记的各项目工作区、当前仓库分支和目录，以及当前仓库的历史目录名。历史随配置持久化，删除、取消关联或移除项目后仍保留，避免复用 Agent 会话目录；Git 写入前即预留名称，创建失败也可能消耗该名称。清空配置会丢失这份历史，无法追溯此前已经删除的目录。
- 仓库父目录中的 `.cota-repository` 用于校验 Cota 管理归属，请勿删除或修改；缺失或不匹配时会阻止目录删除。不再支持旧 UUID 目录的删除特例；不搬迁或删除已有目录（包括旧 `worktrees/dev`、`worktrees/release` 路径），需要时可在“编辑”中移除异常关联后手动处理。
- Worktree 操作统一为新建、编辑和删除，不再提供独立管理面板或外部目录关联入口。右键工作区可在外部程序打开；“编辑”中可重命名、查看目录和状态、重新检查，并结束该项目的异常终端。外部或状态异常的工作树可在“编辑”中显式移除关联，确认后仅结束关联终端并移除工作区与登记，保留目录和分支。
- 普通工作区菜单为「删除工作区」，仅结束终端并移除工作区，不删除本地文件；Worktree 工作区菜单为「删除工作树」，检查并确认后同步删除工作树目录及关联工作区和对应本地分支，仅限本环境内由 Cota 创建的 Worktree。移除项目不删除磁盘目录；取消关联仅结束关联终端并移除登记。
- 删除弹窗只有「删除」和「强制删除」两种确认按钮：存在未提交、未跟踪、忽略文件，或待删除分支未合并时，明确说明后果并要求确认「强制删除」，使用 `git worktree remove --force` 和 `git branch -D`，内容可能无法恢复；否则使用安全删除。取消不会结束终端或修改文件。已初始化子模块、锁定、外部目录和归属不符仍阻断；执行前结束关联终端及子进程并复查，安全确认不会自动升级为强制删除。不再提供“仅删除目录、保留分支”选项；分支实际删除失败时保留并提示。
- 配置直接使用完整 V2，不迁移旧数据或补齐必填字段（包括 `preferences.openWith`；新增 GPU 选项缺省为「自动」）。旧版、缺字段或损坏配置保留原文件并阻止覆盖，需手动移走或修复后重新打开；Host 协议为 6，不兼容的旧 Host 必须先正常结束。

## 源代码管理

点击工作区顶栏的右侧面板图标展开独立的整列工具区域，可拖动分隔线调整宽度；面板顶部左侧为纯图标功能 Tabs，分别为 Git 管理和文件浏览（占位），右侧按钮收起面板。收起后主工作区占满可用空间，再次展开恢复宽度和 Git 内容状态；状态仅在本次应用运行内保留。进入设置时暂时隐藏面板，返回工作区后恢复。

Git 管理跟随当前工作区的真实 Git 工作树；打开仓库子目录时展示整个工作树的更改。非 Git 目录仅提示，不自动初始化仓库。收起面板暂停定时刷新，不取消进行中的 Git 操作，主区域已打开的 Diff 仍可查看。

- 顶部同行展示当前分支、上游和领先 / 落后数量，下方为视图导航。点击分支名搜索并切换本地分支；其他 Worktree 占用的分支不可切换。切换要求工作区干净，不自动 stash、不丢弃改动，也不覆盖被忽略的本地文件；分离 HEAD 时也可选择本地分支。
- 按冲突、已暂存、未暂存、未跟踪分组，支持文件筛选和多选；分组操作作用于该组中勾选的文件，无勾选时作用于该组全部筛选结果（子模块除外）。
- 点击文件在主区域打开只读 Diff，支持并排 / 行内、语法高亮、变更跳转和折叠未修改区域；已暂存比较 HEAD 与暂存区，未暂存比较暂存区与工作文件。同一文件可分别出现在两组。终端保留运行和输出，点击终端标签或“终端”返回；Diff 遮挡的终端不计为正在查看，通知点击仍定位终端。
- 支持单个和批量暂存、取消暂存，以及本地提交。仅提交暂存区，支持首次提交和多行信息；提交草稿、预览文件及滚动位置在本次应用运行内恢复，不持久化到配置。提交保留原生 Hooks 与签名；失败显示诊断并保留草稿，不自动跳过检查或重复提交。
- 丢弃改动须确认，恢复工作文件到暂存区版本，不丢弃已暂存内容；未跟踪文件会永久删除，无法通过 Git 恢复。确认后重新比对文件内容、类型、暂存区与 HEAD，变化则拒绝执行；不递归删除目录、不执行全局清理或硬重置。批量操作失败可能已有部分文件完成，需刷新核对。
- 仅当前面板每 5 秒在窗口可见且聚焦时刷新，并在回焦和操作后刷新。Diff 按需加载，使用随应用打包的 Monaco 和同源 Worker，不从 CDN 获取资源。二进制、非 UTF-8、子模块及超过 2 MiB 的文件不提供文本预览；超过 2 MiB 的工作文件不提供丢弃操作。最多显示 5,000 个变更条目，超出或 Git 输出过大时明确报错，不展示不完整列表。
- 远端操作均须主动点击：选择已配置远端后可 Fetch 或发布当前分支；已有上游时，拉取 / 推送始终使用该上游，而非选框中的发布远端。Fetch 只更新所选远端的分支跟踪引用，不更新工作文件、不获取标签、不清理引用，也不执行自定义的本地分支 Fetch 映射。发布 / 推送会确认分支与提交，确认后复核 HEAD、上游及推送地址；仅推送已审阅的提交，不强推、不镜像、不附带标签或子模块。发布成功后设置上游；若远端已写入但上游设置失败，会明确报告部分成功。
- 点击上游和领先 / 落后数量执行双向同步：先 Fetch 并合并到本地，再确认推送已提交的代码；分叉时创建普通 Merge 提交，不做 Rebase。遇到冲突停止并保留冲突现场，不推送，需在编辑器或终端解决。拉取成功后取消推送或推送失败，已合并内容保留在本地，界面报告未完成的步骤；已完全同步则不重复推送。底层独立拉取操作仍仅允许快进。拉取 / 同步均要求工作区干净，获取后再次核对分支、HEAD 和文件状态，不自动 stash、不覆盖被忽略的本地文件。失败时可能已获取远端引用，工作文件以 Git 实际结果为准。沿用本机 Git 凭证、SSH 和 Hooks；认证、签名或策略失败需在终端处理，不自动安装、修改身份或绕过检查。多推送地址的远端、本地分支上游请使用终端；操作超时后先核对结果，不自动重试。
- “历史”按当前 HEAD 展示提交，每页 50 条、最多 10,000 条；后续分页固定于初次读取的提交快照，不因 Agent 新提交重复或漏项。点击提交可查看相对第一父提交的文件 Diff（首次提交相对空树）；合并提交明确按第一父提交展示，不提供提交图或逐父合并视图。
- “分支比较”选择明确的本地 / 远端引用，比较共同祖先（merge-base）到 HEAD 的已提交内容，不混入暂存区或工作文件。远端引用需主动 Fetch 更新；无共同祖先或浅克隆缺失历史时明确提示。历史与分支预览固定提交对象，即使当前工作文件变化，也不会把新内容混入旧快照。
- 当前不提供逐行暂存、合并编辑器、强推、自动解决冲突或变基。冲突需在外部编辑器或终端解决后暂存；子模块和嵌套仓库写操作请使用终端。Cota 内部 Git 操作与 Worktree 操作共享仓库锁，但无法锁住外部终端或 Agent 的并发写入，请避免同时操作同一仓库；远端操作期间可继续使用终端，但不要并行执行 Git 写入。

## 受管理的 Agent 终端（PRD-05）

右键工作区 → **新建 Agent** → **Pi / Codex / Claude Code**。按登录 Shell 的 PATH 检测 CLI，未安装时先安装对应工具后重新检测；版本检测失败仅显示“版本未知”，不阻止启动。CLI 在工作区真实目录直接启动，使用原生 TUI 和既有账号/权限配置，不拼接 Shell 命令、不自动安装工具。

- **+**、**⌘T** 及新建 Worktree 的默认终端仍为普通 Shell。Agent 与 Shell 共用全局 10 个终端上限。
- **设置 → 常规 → Agent 状态集成** 仅提供各 CLI 的安装状态、安装 / 更新、卸载和检测，不再设总开关或保存启用配置。用户确认安装即授权使用；安装后请新建终端，菜单启动与 Shell 手动启动均通过同一套受管 Hooks / Extension 上报。不通过启动参数单独注入扩展、Hooks 或开启 Codex Hooks；未安装仍可正常启动 CLI，任务状态归为“其他状态”，不显示角标。不自动安装或修复任何文件。
- 集成检测只读；只有用户点击并确认列出的路径后才写入 CLI 配置。Pi 使用原生用户扩展目录，Claude 追加 `settings.json` Hooks，Codex 追加 `hooks.json`。保留用户条目，安装或更新修改已有文件前创建旁路 `.cota-backup-*` 备份；损坏配置、符号链接文件或非 Cota 的同名脚本拒绝覆盖。Codex 的“安装并信任”须明确确认，使用本机 Codex 原生接口获取定义哈希，并仅在 `config.toml` 中追加本次 Cota Hooks 的信任，保留其他信任记录、功能开关与 notify，不跳过权限或企业策略、不安装 CLI；定义变更后需重新确认。信任接口不支持、配置冲突或策略拒绝时明确提示文件已安装但未确认信任成功，可重试或在原生 `/hooks` 审核。检测仍只读文件、不读取信任状态，文件已安装不等于已生效。关闭终端不自动卸载文件。已安装或需要更新的集成可逐项卸载，须再次确认；只删除 Cota 的 Pi 扩展或 Hooks 条目，保留其他配置，不创建备份，不删除共享加载脚本。Dev / 正式版共用配置，卸载均受影响；不结束运行中的 Agent，已加载的集成需重启对应 CLI 后停止生效。
- 新建普通终端后输入 `pi`、`codex` 或 `claude`，无需先向 Agent 发送消息即可尽力识别身份，未安装集成时任务状态归为“其他状态”，不显示角标；收到可信 Hooks / Extension 后在同一身份上更新状态。支持原生进程、Codex 平台二进制及已知 npm Node 入口（含绝对路径符号链接）；自定义启动器、Node 前置参数或歧义路径可能仍需原生事件。进程退出后恢复 Shell 展示，不关闭 Shell、不改变布局恢复方式。Dev / 正式版共用不含凭证的稳定加载器，由各终端环境指向自己的适配器和 Host；缺少 Cota 环境时加载器不向应用上报。
- 识别使用 Host 共享快照：新终端、回车提交或已有 Shell OSC 133 命令边界约 350ms 后检测；有 Agent 时每 750ms、无 Agent 时每 2 秒兜底，查询失败指数退避至 10 秒，不并发堆积。只读可执行名称和进程归属；仅为所属终端的前台 Node 进程补查启动入口，参数只在本机短暂解析，不保存或上报提示词及原始命令行。进程证据不授权 Hooks，也不推断执行中或完成。
- Codex 的共享 daemon 可能保留其他终端环境：菜单启动的 0.156+ 使用 `--no-daemon`；普通 **zsh / bash / fish** 在检测到受管文件后加载仅限本终端的启动包装，支持该参数时自动隔离。zsh 使用私有 `ZDOTDIR` 转发用户启动文件；bash 使用私有 `--rcfile` 按登录顺序加载 `/etc/profile` 和首个用户 profile，不额外重复加载 `.bashrc`；fish 使用 `-C` 在用户配置加载后定义包装。不改用户 Shell 配置，不覆盖 alias / function，不自动安装或修复 Hooks。其他 Shell、绕过包装的绝对路径 / `command codex` 或显式远程 / 共享服务启动不承诺自动隔离；支持时可自行使用 `codex --no-daemon`。包装只影响新建终端；进程发现只确认运行身份，不推断执行中或完成，也不授权 Hooks。无法证明事件进程属于本终端前台任务时拒绝绑定，不能把事件归给其他标签。
- 配置路径尊重应用继承的 `PI_CODING_AGENT_DIR` / `CODEX_HOME` / `CLAUDE_CONFIG_DIR`，以检测及确认显示的路径为准；仅在 Shell 启动脚本中另行切换的配置目录需自行核对。
- Pi **1.3+（1.x）** 使用最终 `agent_settled` 核对原生结算结果，区分完成、失败、中断与结果未知。Claude Code **2.1.196+（2.x）**、Codex **0.124+（0.x）** 使用原生轮次 ID；Stop 立即表示**本轮结束，而非任务成功**，后续原生活动可纠正为执行中，不等待 `idle_prompt`，也不从终端静默推断成功。Claude 的 StopFailure 表示失败；Codex **0.159+** 接入原生 Interrupt。版本未知、不支持、组件缺失或事件失效时归为**其他状态**，不显示角标，基本 CLI 启动不受影响。以上为适配范围，尚未完成真实 CLI 版本矩阵验收。
- 原生提问工具与权限请求表示待处理；只有对应请求结束才清除等待，缺少请求 ID 时保留至该 Agent 本轮结束，平行工具不会误清。Claude 与 Codex **0.145+** 跟踪原生子 Agent，同一 ID 结束后可再次恢复；主 Agent 结束但子任务待处理 / 仍运行时，不显示整体结束。Claude 仅使用主 Agent Stop / StopFailure 的完整后台快照，按子任务 ID 对账去重，子 Stop 不复用可能滞后的快照；缺字段不清除旧证据，未知类型或超限降级未知。后台快照独立计时，普通主轮次活动不会延长其五分钟有效期；不读取会话日志或猜测取消。
- Agent 展示执行中、待处理、本轮结束、已完成、执行失败、连接失败、已中断；其余统一为“其他状态”，不显示角标（包括启动、关闭、未知、退出和空闲），底层生命周期状态不变。工作区按待处理、连接失败、未读失败、执行中、未读结束、已中断、其他状态聚合，没有活动 Agent 的普通 Shell 不参与。工作区左侧默认以绿色小圆点表示存在终端或 Agent，均不存在时显示灰点；有非“其他状态”的 Agent 提示时优先显示状态图标，否则保留圆点。后台事件不抢焦点；仅实际可见且窗口聚焦的终端自动标记已读。完成 / 本轮结束提醒须持续聚焦 2 秒才标记已读并隐藏角标；失焦或切换终端取消计时，再次聚焦重新计时。已读不会抹掉真实活动状态。
- 后台终端收到可信的完成、失败或待处理状态时发送原生系统通知；仅明确成功显示“已完成”，结果未知的结束显示“本轮结束”。当前正在查看的终端不重复打扰，同轮状态与已读回执去重，恢复快照不补发历史通知。点击通知聚焦对应工作区与终端，目标已关闭则忽略；通知不包含提示词、回复或工具内容，不替用户批准权限。系统通知权限关闭或不可用时，界面状态与未读提醒仍正常工作。
- Host 独立接收元数据事件，不依赖 xterm 是否附着；事件通道与终端管理通道隔离，管理凭证不传给 CLI；普通终端接入凭证只能为所属终端报到，经 PID / 启动时间 / 进程树 / 前台组核验后映射到单次 Agent 的独立身份与凭证。不采集提示词、回复或工具内容，不根据终端输出、静默或按键猜测完成；Hooks 五分钟无活动事件只会降级未知，不会标记完成。
- Host 存活时重载界面可恢复同一 Agent，不重复启动；仅有保存的布局不会自动重启 Agent。菜单直接启动的 Agent 退出后保留最后屏幕和退出码；Shell 内手动启动的 Agent 退出后恢复原 Shell 标签。
- 关闭活跃 Agent 需确认；工作区删除和退出应用沿用现有进程树清理。清理失败保留会话及诊断；进程未退出时恢复输入与尺寸调整，可重试关闭，但已撤销的状态集成保持未知。真实退出事件优先。

## 在外部程序中打开工作区

右键工作区 → **打开于**，固定提供「文件管理器」，无需配置；使用系统文件管理器（macOS 为访达）打开目录。添加应用的内置选项仅提供 Zed（`zed`）和 VS Code（`code`），需先安装对应命令行工具；已有配置不会被覆盖。Zed、VS Code 使用 `simple-icons` npm 包的单色图标，文件管理器使用 Lucide `FolderOpen` 文件夹图标，未知程序使用通用图标。图标随 Cota 打包，无需联网，也不读取本机应用图标。为保留 VS Code 图标，依赖锁定为 `simple-icons@12.4.0`。
在 **设置 → 集成 → 打开方式** 中可添加、编辑或删除程序：命令与参数分开填写，参数支持 `{path}` 工作区目录占位符（如 `--new-window {path}`）；不填写占位符时自动追加目录。支持可执行文件绝对路径，不执行 Shell 表达式。

## FAQ / 常见问题

### macOS 提示“无法验证 Cota.app 恶意软件”

如果在 macOS 上打开应用时提示“Apple无法验证 Cota.app 是否包含可能危害Mac安全或泄漏隐私的恶意软件”，可在终端运行以下命令清除隔离标记：

```sh
sudo xattr -r -d com.apple.quarantine /Applications/Cota.app
```

> **注**：如果 `.app` 文件存放在其他路径（如未移动至 `/Applications`），请将命令中的路径替换为实际的 `Cota.app` 路径。
