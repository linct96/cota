# Cota

## Git / worktree 测试

- 无需安装 Git：`pnpm exec vitest run tests/git-unit.test.ts tests/worktrees-unit.test.ts`，覆盖解析、表单校验、缓存、mock 托管 API 及缺少 Git 的降级行为。
- 真实 Git 集成：`pnpm exec vitest run --project git`，使用独立临时仓库及本地 bare 远端，不访问真实托管平台。Git 测试文件逐个运行，避免大量 Git 子进程争抢资源；用例内部仍验证并发操作。
- 本机缺少 Git 时，上述集成测试会明确提示并跳过；CI 缺少或无法执行 Git 时直接失败，不视为验证通过。各场景独立初始化，不依赖前一个测试的执行顺序。

## E2E 测试

macOS 下运行 `pnpm test:e2e`，使用真实 Electron、Git 和 PTY 验证核心闭环。测试使用独立临时目录，不读取真实账号、不写远端。运行方式、覆盖范围及故障排查见 [E2E 测试流程](docs/e2e.md)。

## Cortana 账号管理

最左侧导航中的 **Cortana → 账号管理** 用于管理 Codex、Claude Code、Pi 和 Grok 的本机账号。支持浏览器授权（Pi 使用本地登录导入）、凭据导入、账号切换、重命名、删除、排序和用量刷新。Codex 与 Claude Code 还支持 API 账号。

账号保存在当前 Cota 用户目录的 `cortana.sqlite3` 中，仅创建一张 `accounts` 业务表，凭据通过 Electron `safeStorage` 使用系统密钥加密。开发版与正式版使用各自的用户目录。

检测到 `~/.cortana/app.sqlite3` 时，可使用「导入 Cortana」复制已有账号。导入以只读方式访问源数据库，跳过重复账号及不支持的产品；删除 Cota 中的账号不会退出 CLI 的当前登录。切换账号前会检查尚未保存的外部登录，并在写入失败时恢复已修改的认证文件。切换后，已启动的 CLI 可能需要重启才能使用新账号。

本阶段仅迁移账号模块。依赖协议转换网关或自定义模型的部分 API 账号可导入、查看和管理，在相关模块接入前暂不可切换。账号切换保留配置中的其他设置；TOML 配置由解析器重新序列化，注释和排版可能改变。Cortana 的自定义 `codex_home` 设置不会导入，Codex 目标目录使用 `CODEX_HOME` 或默认的 `~/.codex`。

账号适配逻辑移植自 Cortana，原始许可见 `resources/licenses/cortana.txt`。

## 退出与会话恢复

- 普通退出（macOS `Cmd+Q` 或关闭窗口）只断开界面连接，不结束 Terminal Host 中的终端、Agent 和服务；下次打开会重新连接原会话，不重新执行命令。
- 退出期间显示全窗口状态遮罩，等待正在进行的工作区变更、保存设置并清理界面资源，不再将正常退出中的后台刷新作为错误提示。
- 应用菜单中的 **结束全部任务并退出** 会先确认，再依次结束终端与程序。删除工作区、关闭单个终端的安全确认保持不变。
- CLI 安装、工作树初始化和提交信息生成由界面主进程托管，退出时仍会安全停止；后台终端不再享有界面进程提供的防休眠与桌面通知。
- 会话仅在同一用户目录及兼容的 Host 协议下恢复，不保证跨应用更新存活；协议不兼容时不会自动终止旧会话。

## 工作树初始化

项目菜单 → **工作树初始化配置** 可设置初始化命令和需要从项目目录复制的本地文件（每行一个相对路径）。配置仅保存在本机；保存、打开项目或重新打开工作区都不会自动执行。

新建工作树时可勾选「创建后初始化环境」；已有工作树可通过右键菜单 **初始化环境 / 查看日志** 手动执行、停止或重试。每次执行均显示命令、来源和目标目录并要求确认。先复制文件，再使用当前配置的 Shell 在工作树目录中运行非交互命令。

- 已有目标文件不覆盖；不支持目录、符号链接、`.git`、`node_modules` 或单个超过 10 MB 的文件。
- 失败、停止或取消执行不会删除工作树；重试不会回滚先前的修改，请自行保证命令可安全重复执行。
- 初始化期间禁止删除或取消关联该工作树；关闭日志不停止任务，退出 Cota 会停止正在运行的初始化。
- 本机仅保留最近一次结果和末尾 65,536 字符日志（正常结束时落盘），输出可能包含敏感信息。异常退出后不会自动重试，请先检查残留进程。
- 此功能用于会自行结束的初始化命令；长驻进程请使用下方的工作区服务。

## 工作区服务

在 **快捷命令** 中将运行类型设为 **长驻服务**，再从工作区顶部的快捷命令启动。服务与当前工作区绑定，每项定义在同一工作区只运行一个实例；再次运行会打开已有日志。普通命令的行为不变。

启动后，工作区顶部的 **服务** 可查看状态、打开日志、停止或重启，并在配置端口时打开 `http://127.0.0.1:端口`。服务使用原有终端 Host 和滚动日志，切换工作区、关闭面板或普通退出应用不会停止；关闭对应终端、删除工作区或选择「结束全部任务并退出」时沿用安全确认与进程树清理。重启保留旧终端日志，因此需要一个空闲终端名额。

- 端口可留空、指定 `1024–65535`，或填 `auto` 自动分配。启动前检查占用，并通过 `PORT` / `COTA_PORT` 传给命令；不会修改项目文件或自动补命令参数。工具必须实际读取环境变量，例如 Bash/Zsh 下 `pnpm exec vite --port "$PORT" --strictPort`（PowerShell 使用 `$env:PORT`）。
- 端口检查与子进程绑定间仍有竞态；工具应配置严格端口模式，避免静默改用其他端口。未配置端口不提供打开入口。
- 仅支持前台命令，不要使用 `&`、daemon 或自行脱离进程树的守护进程。命令退出即结束服务，不自动重启；运行中不代表已经就绪，不提供健康检查或反向代理。
- 服务仍计入全局 50 个终端上限。删除或编辑定义不会停止已有实例；停止与日志入口保留，重启使用当前定义。应用重载或普通退出后重新打开会连接存活的 Host，不重新执行命令；已停止的服务不会自动重启。

# FAQ / 常见问题

## macOS 提示“无法验证 Cota.app 恶意软件”

如果在 macOS 上打开应用时提示“Apple无法验证 Cota.app 是否包含可能危害Mac安全或泄漏隐私的恶意软件”，请先确认应用来源可信，再在终端运行以下命令清除隔离标记：

```sh
sudo xattr -r -d com.apple.quarantine /Applications/Cota.app
```

> **注**：如果 `.app` 文件存放在其他路径（如未移动至 `/Applications`），请将命令中的路径替换为实际的 `Cota.app` 路径。
