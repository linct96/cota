# Cota

## 代码检查

`pnpm lint` 使用 `@tanstack/oxlint-config`，配置位于 `oxlint.config.mts`；通过 `oxlint-tsgolint` 启用类型感知检查，同时保留 correctness、React Hooks 与无障碍检查。根 `tsconfig.json` 覆盖源码、测试和工具配置，主进程与前端的独立 typecheck 仍使用各自的 tsconfig。现有 `.cjs` 工具文件允许 CommonJS，构建产物和测试报告不参与检查；警告同样会使命令失败。数组类型统一为 `T[]` / `readonly T[]`；类型导入使用顶层 `import type`，回调类型使用函数属性签名，并按规则排序导入成员。格式化仍由 `pnpm format` 负责。

## 测试

| 命令               | 范围                                                         |
| ------------------ | ------------------------------------------------------------ |
| `pnpm test:unit`   | 纯逻辑、mock 与临时文件测试，不要求 Git、真实 PTY 或应用构建 |
| `pnpm test:git`    | 真实 Git 集成，包括依赖 Git 的 Host 工作树和文件忽略规则测试 |
| `pnpm test:native` | 真实 Shell、PTY、进程树、端口与构建后 Host 集成              |
| `pnpm test`        | Vitest 按 unit → git → native 顺序执行全部非 UI 测试         |
| `pnpm test:e2e`    | 构建后由 Playwright 驱动真实 Electron UI，仅 macOS           |
| `pnpm test:all`    | macOS 下依次执行 Vitest 与 E2E，任一失败即停止               |

Vitest 与 Playwright 均单 worker、文件串行、零重试；用例内部针对产品并发行为的检查保留。混合测试文件按其最强外部依赖归类，避免单元测试入口隐含依赖真实工具。

- Git 集成使用独立临时仓库及本地 bare 远端，不访问真实托管平台。本机缺少 Git 时明确提示并跳过；CI 缺少或无法执行 Git 时失败，不视为验证通过。
- native 中的 `node-pty` 由 Electron 的 Node 模式执行，保留真实 ABI 验证；Host 测试先重新构建，再验证独立进程和会话重连。`pnpm test:pty` / `pnpm test:host` 保留为对应 Vitest 用例的快捷入口。
- `test:all` 直接串联 `pnpm test && pnpm test:e2e`，不生成跨框架汇总报告。测试驱动集中在 `tests/native/`，Vitest 与 Playwright 保留各自的输出和报告。
- Host 的连接、断言与清理由 `tests/native/host.test.ts` 直接管理；PTY 的原生调用通过同一测试文件内的 Electron 子进程执行，不再维护独立 smoke 脚本。
- 发布流程设置 `COTA_TEST_PACKAGED=1` 后运行 `pnpm test:host`，复用同一用例验证 `release/` 中的实际安装包，跳过开发构建。

测试文件按被测职责组织：`tests/main/<模块>/` 覆盖主进程，`tests/renderer/<模块>/` 覆盖前端状态与纯逻辑，`tests/native/` 保留真实 Shell、PTY 和独立进程集成。共用环境放在邻近的 `*.fixture.ts`，跨模块 CLI 环境放在 `tests/helpers/`；fixture 不包含测试用例。按文件定位运行，例如 `pnpm exec vitest run --project unit tests/renderer/workspace/preview-tabs.test.ts`。

E2E 使用独立 Home、用户目录与项目，不读取真实账号、不写远端。运行方式、覆盖范围及故障排查见 [E2E 测试流程](docs/e2e.md)。

## 数字输入组件

通用组件位于 `src/renderer/src/components/ui/input-number.tsx`，已接入终端外观、最低对比度和自定义缓冲行数。沿用 28px 输入框，右侧上下箭头支持点击与长按，也可使用方向键微调；默认不通过滚轮改值。

```tsx
<InputNumber
  id="font-size"
  min={8}
  max={48}
  step={1}
  value={value}
  onValueChange={setValue}
  inputProps={{ 'aria-label': '字号' }}
/>
```

`value` / `onValueChange` 使用 `number | null`，`null` 表示清空或尚不可解析的临时输入（如 `-`），避免表单误用上一次的有效值；支持 `defaultValue`、`disabled`、`readOnly` 与 `onValueCommitted`。`id`、`name`、范围和步长传给组件，输入框的 ARIA、placeholder 与 ref 通过 `inputProps` 传入。默认保留手动输入的越界值，由表单校验；按钮和方向键始终受范围限制。小数步长由 Base UI 处理；默认 Alt 使用相同步长，Shift 使用十倍步长。

## Git 提交

右侧 Git 面板只提交已暂存的更改。提交信息为空或仅含空白时，提交及提交并推送按钮禁用；输入框失焦不显示空值错误，实际提交时仍校验内容。可手动填写或使用 Pi 生成提交信息。

## Git 操作失败

拉取或同步因本地改动可能被覆盖而中止时，弹窗提示先提交更改或使用 `git stash` 保存工作区改动；不会自动 stash、丢弃文件或继续推送。

弹窗使用等高的 **Git 日志** 和 **命令输出** 标签页，分别展示本次操作的命令、耗时和执行结果，以及失败命令及其输出；不提供折叠或收起。诊断仅保留在内存中，不写入磁盘；日志保留末尾 64,000 字符，命令输出保留前 64,000 字符，HTTP(S) URL 中的账号凭据会隐藏。

## 冲突文件对比

Git 面板中的冲突文件可在现有 Monaco Diff 中只读查看：“冲突双方”对比 Git stage 2 与 stage 3；“当前处理结果”对比 stage 2 与工作区内容。缺失版本标记为“不存在”，与空文件区分；阶段名称不使用可能在 rebase 中产生歧义的“我的／对方”。单文件及“查看全部变更”均支持切换视图。

不提供内置冲突编辑、接受某一侧或自动暂存。二进制、非 UTF-8、超过 2 MiB、符号链接及子模块等不支持的冲突仍提示外部处理。外部处理后需手动暂存以标记已解决。

## Agent 状态集成

点击状态集成的「安装」「更新」或「信任」后直接执行；仅「卸载」仍需确认。修改已有配置前会创建备份，并保留其他 Hooks。短操作仅禁用按钮防止重复执行，不切换 loading；CLI 检测、检查更新、Hooks 信任和代码托管检测等等待操作超过 200ms 才显示 loading，显示后至少保留 300ms，不人为延迟实际操作。

设置中的 Codex 状态集成按阶段显示操作：未安装时显示「安装」；安装后替换为「信任」和「卸载」；信任后仅显示「卸载」。安装只写入 Hooks 文件，不授予信任；安装后可单独点击「信任」，或启动 Codex 终端，通过 `/hooks` 自行审核。重新检测会通过 Codex 原生接口读取信任状态，不会自动授予信任。Cota 的信任操作只处理已安装的 Cota Hooks，不改变其他 Hooks 的信任、功能开关或 CLI 权限；仍受企业策略限制。安装或信任后请新建终端。

## Cortana 账号管理

最左侧导航中的 **Cortana → 账号管理** 用于管理 Codex、Claude Code、Pi 和 Grok 的本机账号。支持浏览器授权（Pi 使用本地登录导入）、凭据导入、账号切换、重命名、删除、排序和用量刷新。Codex 与 Claude Code 还支持 API 账号。

账号保存在当前 Cota 用户目录的 `providers.json` 中，凭据通过 Electron `safeStorage` 使用系统密钥加密。开发版与正式版使用各自的用户目录。旧版 SQLite 数据不会被读取或迁移，请重新添加或从当前 CLI 登录导入账号。

账号配置写入使用 `providers.json.lock` 协调，并在原子替换前再次检查文件是否被修改；刷新会重新读取外部更新。不遵守锁协议的编辑器仍可能在最终检查后与提交竞争，请退出 Cota 后再手动编辑文件。

删除 Cota 中的账号不会退出 CLI 的当前登录。切换账号前会检查尚未保存的外部登录，并在写入失败时恢复已修改的认证文件。切换后，已启动的 CLI 可能需要重启才能使用新账号。

账号切换保留配置中的其他设置；TOML 配置由解析器重新序列化，注释和排版可能改变。Codex 目标目录使用 `CODEX_HOME` 或默认的 `~/.codex`。

账号适配逻辑移植自 Cortana，原始许可见 `resources/licenses/cortana.txt`。

## 退出与会话恢复

- 普通退出（macOS `Cmd+Q` 或关闭窗口）只断开界面连接，不结束 Terminal Host 中的终端、Agent 和服务；下次打开会重新连接原会话，不重新执行命令。
- 退出期间显示全窗口状态遮罩，等待正在进行的工作区变更、保存设置并清理界面资源，不再将正常退出中的后台刷新作为错误提示。
- 应用菜单中的 **结束全部任务并退出** 会先确认，再依次结束终端与程序。删除工作区、关闭单个终端的安全确认保持不变。
- CLI 安装按钮打开官方安装指南；更新统一执行对应 CLI 的 `update` 命令，保留进度与日志。
- CLI 更新、工作树初始化和提交信息生成由界面主进程托管，退出时仍会安全停止；后台终端不再享有界面进程提供的防休眠与桌面通知。
- 会话仅在同一用户目录及兼容的 Host 协议下恢复，不保证跨应用更新存活；协议不兼容时不会自动终止旧会话。

## 项目分组

项目面板右上角 **⋯ → 新建分组** 可创建自定义分组；项目菜单中的 **移动到分组** 用于调整归属，每个项目只属于一个分组。从分组菜单添加的项目会自动归入该组。

分组支持重命名、展开与收起，并在重启后恢复折叠状态。删除分组只将项目移回未分组，不关闭工作区或终端，也不删除本地文件。没有自定义分组时，面板保持平铺列表。

## Agent 列表

项目面板底部的 **Agents** 默认收起，工作区内保留 Agent 快捷图标。展开后，底部汇总所有项目与工作区的 Agent，显示终端名称、状态及所属项目 / 分支，工作区内不再重复展示图标。点击列表项可定位到对应终端；上下区域独立滚动，可拖动分隔线调整高度。

Agents 与 Git 的 **Commit 对比 / 历史评审记录** 共用折叠标题和拖拽布局：点击整行或使用键盘展开、收起，右侧箭头指示状态。上方区域至少保留 20% 高度，下方面板展开时至少为 6rem、收起为 2rem，窗口缩放时按比例调整。Agents 首次展开占可用高度的 40%，再次展开恢复收起前的高度；拖动分隔线也会同步折叠状态。

## 工作树初始化

项目菜单 → **工作树初始化配置** 可设置初始化命令和需要从项目目录复制的本地文件（每行一个相对路径）。配置仅保存在本机；保存、打开项目或重新打开工作区都不会自动执行。

新建工作树时可勾选「创建后初始化环境」；已有工作树可通过右键菜单 **初始化环境 / 查看日志** 手动执行、停止或重试。每次执行均显示命令、来源和目标目录并要求确认。先复制文件，再使用当前配置的 Shell 在工作树目录中运行非交互命令。

- 已有目标文件不覆盖；不支持目录、符号链接、`.git`、`node_modules` 或单个超过 10 MB 的文件。
- 失败、停止或取消执行不会删除工作树；重试不会回滚先前的修改，请自行保证命令可安全重复执行。
- 初始化期间禁止删除或取消关联该工作树；关闭日志不停止任务，退出 Cota 会停止正在运行的初始化。
- 本机仅保留最近一次结果和末尾 65,536 字符日志（正常结束时落盘），输出可能包含敏感信息。异常退出后不会自动重试，请先检查残留进程。
- 此功能用于会自行结束的初始化命令；长驻进程请使用下方的工作区服务。

## 快捷命令

使用 Fish 时，普通快捷命令会新建终端标签，等待输入就绪后填入完整命令并回车；可用 ↑ 调回命令，Ctrl+C 中断后可继续使用终端。多行命令整段提交，历史记录遵循 Fish 自身设置。其他 Shell 和长驻服务的执行方式不变。

## 工作区服务

在 **快捷命令** 中将运行类型设为 **长驻服务**，再从工作区顶部的快捷命令启动。服务与当前工作区绑定，每项定义在同一工作区只运行一个实例；再次运行会打开已有日志。普通命令的行为不变。

启动后，工作区顶部的 **服务** 可查看状态、打开日志、停止或重启，并在配置端口时打开 `http://127.0.0.1:端口`。服务使用原有终端 Host 和滚动日志，切换工作区、关闭面板或普通退出应用不会停止；关闭对应终端、删除工作区或选择「结束全部任务并退出」时沿用安全确认与进程树清理。重启保留旧终端日志，因此需要一个空闲终端名额。

- 端口可留空、指定 `1024–65535`，或填 `auto` 自动分配。启动前检查占用，并通过 `PORT` / `COTA_PORT` 传给命令；不会修改项目文件或自动补命令参数。工具必须实际读取环境变量，例如 Bash/Zsh 下 `pnpm exec vite --port "$PORT" --strictPort`（PowerShell 使用 `$env:PORT`）。
- 端口检查与子进程绑定间仍有竞态；工具应配置严格端口模式，避免静默改用其他端口。未配置端口不提供打开入口。
- 仅支持前台命令，不要使用 `&`、daemon 或自行脱离进程树的守护进程。命令退出即结束服务，不自动重启；运行中不代表已经就绪，不提供健康检查或反向代理。
- 服务仍计入全局 50 个终端上限。删除或编辑定义不会停止已有实例；停止与日志入口保留，重启使用当前定义。应用重载或普通退出后重新打开会连接存活的 Host，不重新执行命令；已停止的服务不会自动重启。

# FAQ / 常见问题

## macOS 提示“无法验证 Cota.app 恶意软件”

如果在 macOS 上打开应用时提示“Apple无法验证 Cota.app 是否包含可能危害Mac安全或泄漏隐私的恶意软件”，请先确认应用来源可信，再在终端运行以下命令清除隔离标记：

```sh
sudo xattr -r -d com.apple.quarantine /Applications/Cota.app
```

> **注**：如果 `.app` 文件存放在其他路径（如未移动至 `/Applications`），请将命令中的路径替换为实际的 `Cota.app` 路径。
